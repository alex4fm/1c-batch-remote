# Удалённый режим 1c-batch

 Используем — только удалённый режим, включая localhost; при ошибке файла или связи не переходи к локальному BAT. Скрипты сами читают настройки: не читай и не выводи токен, не включай его в команды и не передавай `remote`.

В `remote` параметр `url` содержит схему, адрес сервера и порт, например `http://85.85.85.10:80`, без пути API. Скрипты добавляют `/batch/v1` самостоятельно.

Для передачи перечисли отдельными аргументами все необходимые файлы внутри проекта (не каталоги):
```bash
python -X utf8 skills/1c-batch/remote/remote-scripts/upload_files.py <файл1> [файл2 ...]
```
Скрипт проверяет подтверждение путей, размеров и контрольных сумм; код 0 означает успешное подтверждение всех файлов.
Остальные аргументы соответствуют интерфейсам BAT.Только после этого запускай нужный BAT отдельной командой:
```bash
python -X utf8 skills/1c-batch/remote/remote-scripts/run_bat.py '<команда одной строкой>'
```
Для запуска скриптов используй `call "scripts\<имя- BAT>.bat" [аргументы BAT ...]`. Скрипт ждёт конечного статуса, получает полный журнал при усечении; код 0 означает succeeded и нулевой код BAT. Проверь журнал и фактический результат. При ошибке или неподтверждённых файлах зависимую команду не запускай.

UUID выводится в stderr до отправки: сохрани его. При потере ответа или истечении ожидания продолжай опрос прежней операции командой `python -X utf8 skills/1c-batch/remote/remote-scripts/run_bat.py --resume UUID`, не создавая новую операцию вслепую. При interrupted установи фактическое состояние до повторного изменения базы. Если операция удалённо не поддерживается, сообщи об ограничении.
