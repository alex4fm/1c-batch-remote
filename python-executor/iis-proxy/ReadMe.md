# Установка IIS для прокси 1c-batch


## 1. Компоненты Windows (пропустить, если IIS уже установлен)

Откройте **Включение или отключение компонентов Windows** и в разделе **Службы IIS** отметьте:

| Путь в показанном окне | Для чего |
|---|---|
| Службы Интернета → Безопасность → **Фильтрация запросов** | Ограничения запросов, в том числе размера загружаемого ZIP; на этапе настройки лимит нужно увеличить. |
| Службы Интернета → Общие функции HTTP → **Ошибки HTTP** | Настройка передачи клиенту готовых ошибок Python-исполнителя. |
| Средства управления веб-сайтом → **Консоль управления IIS** | Графическая настройка и проверка сайта и модулей. |

Для первого запуска и диагностики также отметьте:

- Службы Интернета → Общие функции HTTP → **Документ по умолчанию** и **Статическое содержимое**: стандартная стартовая страница для проверки IIS. Для передачи запросов к Python сами по себе не нужны.
- Службы Интернета → Проверка работоспособности и диагностика → **Ведение журнала HTTP**: журнал для диагностики запросов.
- Если в разделе «Безопасность» доступна **Анонимная проверка подлинности**, оставьте её включённой: Bearer-токен проверяет Python-исполнитель. На приведённом снимке этот пункт не отображается.

Родительские разделы и необходимые зависимости Windows отметит автоматически. Не требуется выбирать все пункты родительского раздела. Для этого прокси не нужны ASP, ASP.NET, CGI, WebSocket, WebDAV, FTP, Windows/обычная проверка подлинности, совместимость с IIS 6 и сжатие. Microsoft указывает ASP.NET как условие своего учебного примера с ASP.NET-страницами; здесь сервер приложения работает отдельно на Python.

Нажмите **ОК**, дождитесь установки и при запросе Windows перезагрузите компьютер.

## 2. Следующий этап: модули прокси

В окне компонентов Windows этих модулей нет. После установки IIS отдельно понадобятся:

1. [URL Rewrite 2.1](https://www.iis.net/downloads/microsoft/url-rewrite) — правило изменения пути `/batch/`.
2. [Application Request Routing 3](https://www.iis.net/downloads/microsoft/application-request-routing) — пересылка HTTP-запросов. Установить также зависимости, указанные установщиком ARR.

## 3. Настройка IIS-прокси 1c-batch

### Куда копировать web.config

Скопируйте `web.confif.example` в корень сайта IIS (без `.example`). Для стандартного сайта
`Default Web Site` это `C:\inetpub\wwwroot\web.config`.

Если в корне уже есть `web.config`, не заменяйте его: объедините настройки.

### Включите ARR

1. Откройте **Диспетчер служб IIS** (`inetmgr`) с правами администратора.
2. В панели **Подключения** выберите узел сервера над списком сайтов.
3. Откройте **Application Request Routing Cache**.
4. В панели **Действия** выберите **Server Proxy Settings...**.
5. Установите флажок **Enable proxy** и нажмите **Apply**.
6. Откройте **Server Proxy Settings...** ещё раз и убедитесь, что флажок включён.

Настройка применяется ко всему серверу IIS.
