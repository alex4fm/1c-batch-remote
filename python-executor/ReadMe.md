# Python-исполнитель для 1c-batch

Исполнитель принимает файлы проекта и запускает команды 1С на удалённом компьютере.

## Установка и запуск

1. Установите 64-разрядный Python, отметив **Add python.exe to PATH**. Проверенный вариант — [Python 3.13](https://www.python.org/downloads/release/python-31314/).
2. Разместите папку `python-executor` на удаленном сервере, где доступен конфигуратор. Скопируйте `.1c-devbase.bat` в корень `python-executor` - заполните настройки в файле.
При редактировании следите, чтобы файл сохранился **в UTF-8, без BOM, с CRLF**. Встроенный блокнот сохраняет с BOM. В некоторых версиях windows, некорректно считываются файлы, если перенос только LF.
3. При необходимости измените `port` в `settings.json` (по умолчанию `8765`).
4. Запустите `start-python_executor.cmd`. При первом запуске будет создано окружение `python-executor/venv` и установлены зависимости; нужен доступ в интернет. Оставьте окно открытым; для остановки нажмите Ctrl+C.



Файлы проекта размещаются непосредственно в корне `python-executor`: администратор может скопировать их вручную или передать через API. Пути загружаемых файлов и рабочий каталог команд отсчитываются от этого корня.

Пример расположения файлов проекта:

```text
python-executor/
└── src/
    ├── cf/        — конфигурация
    ├── cfe_main/  — расширение
    ├── epf/       — внешние обработки
    └── ert/       — внешние отчёты
```

Прямой адрес API — `http://<путь к серверу>:8765/batch/v1`, через Apache/IIS прокси — `http://SERVER/batch/v1`. Формат запросов, авторизация и ссылки результатов одинаковы. Apache/IIS остаётся вариантом, если отдельный внешний порт открыть нельзя.

В стандартной конфигурации Apache или IIS обращается к исполнителю по адресу `127.0.0.1:8765`. Если изменить порт исполнителя, укажите тот же порт в настройках прокси: для Apache — в адресах `ProxyPass` и `ProxyPassReverse`, для IIS — в атрибуте `url` правила URL Rewrite в файле `web.config`.

По умолчанию лимиты на передаваемые файлы: ZIP 32 МиБ, распакованные данные 128 МиБ, 10 000 файлов, обработка 120 секунд. При слишком большом запросе Waitress может вернуть текстовый HTTP 413.


#### Подробности по файлу настроек settings.json:

Параметры находятся в `settings.json`. После их изменения перезапустите исполнитель. Файл должен оставаться корректным JSON: комментарии в нём не поддерживаются.

- `port` — порт, на котором исполнитель принимает подключения; по умолчанию `8765`.
- `token` — токен авторизации: строка из 36 шестнадцатеричных символов без дефисов. Пустое или некорректное значение вызывает ошибку запуска.
- `artifactRetentionDays` — срок хранения операций в днях, по умолчанию `7`. При запуске исполнитель полностью удаляет операции, созданные не менее указанного числа дней назад, вместе с журналами и статусами.
- `consoleEncoding` — кодировка вывода команд для записи журнала. Для поставляемых скриптов указана `utf-8`.
- `limits` — ограничения на загрузку файлов и выполнение команд:
  - `maxZipBytes` — максимальный размер ZIP в байтах.
  - `maxUnpackedBytes` — максимальный размер распакованных данных в байтах.
  - `maxFiles` — максимальное число файлов в загрузке.
  - `updateTimeoutSeconds` — время обработки загрузки в секундах.
  - `executionTimeoutSeconds` — время выполнения команды в секундах, по умолчанию 600.
  - `resultTimeoutSeconds` — время на завершение и сохранение результата операции в секундах, по умолчанию 30; также используется при остановке оставшихся процессов после перезапуска.
