
# Удалённый режим 1c-batch

## Назначение проекта

Проект поставляется как дополнение для скилла [**1c-batch от Владимира Харина**](https://github.com/vladimir-kharin/1c-batch).
Позволяет ретранслировать запросы вместо локальных на удаленный компьютер, где расположена база и платформа 1С.
Полезен в том случае, когда базу с удаленного сервера получить на локальный компьютер не представляется возможным.
А так же для тех кто привык работать на удаленном сервере (обычно по RDP) и не копировать постоянно файлы базы и/или конфигурации.

##  Требования

* На удаленном сервере потребуются административные права. Чтобы установить python.
* На сервере должен быть доступен внешний порт, либо локальный компьютер с сервером должны находиться в одной локальной сети (например VPN).

Если локальный компьютер и сервер в одной локальной сети, то проксирование через appache или iss не потребуется, т.к. порт исполнителя будет доступен при прямом обращении.
В противном случае потребуется проксирование. appache/iis будут проксировать внешние запросы на локальный исполнитель.
Так же если есть возможность настроить перенаправление портов (на роутере, например), то можно так же обойтись без проксирования. Потребуется только опубликовать порт исполнителя.


## Состав комплекта

Комплект содержит серверный исполнитель и клиентские файлы навыка:

- `python-executor/` — исполнитель и инструкции по его установке на удаленном компьютере 1С.
- `remote/` — инструкция и скрипты удалённого режима для навыка 1c-batch; файл `remote` внутри папки — образец настроек локального проекта.

## Удаленный компьютер 1С 

1. Скопируйте папку `python-executor` на удалённый компьютер, где доступны платформа и база 1С. Установить желательно в корень диска.
2. Следуйте инструкции в файле [ReadMe](python-executor/ReadMe.md) в корне папки.
3. Если потребуется проксирование, то следуйте следующим инструкциям для [Apache](python-executor/apache-proxy/ReadMe.md) или [IIS](python-executor/iis-proxy/ReadMe.md)

## Локальный компьютер

1. Скопируйте папку `remote` из комплекта в папку навыка `1c-batch`, и файл `SKILL.md` (поддерживает bat скрипты из более ранней версии 1c-batch)
2. Если в `SKILL.md` ещё нет следующего раздела, добавьте его:

   ```markdown
   ## Режим удаленного рабочего стола

   Проверь наличие файла `remote` в корне проекта, не читая его содержимое. Если файл
   существует, прочитай [инструкцию удалённого режима](remote/skill-remote.md) и следуй
   ей. Если файла нет, не читай эту инструкцию и используй локальный режим ниже.
   ```

3. Скопируйте файл-образец `remote` из этой папки в корень локального рабочего проекта. Имя файла — `remote`, без расширения.
4. В файле `remote` укажите `url` сервера со адресом и портом. Токен по умолчанию уже совпадает с серверным; если вы его заменили, укажите в `token` новое значение из серверного `settings.json`:

   ```text
   url=http://SERVER:80
   token=ВАШ_ТОКЕН
   ```

   Например, при прямом подключении используйте порт исполнителя `8765`, а при подключении через прокси — адрес и порт прокси. Для удалённого подключения используйте HTTPS, если оно настроено на прокси.

Наличие файла `remote` в корне проекта переключает skill в удалённый режим, в том числе при обращении к `localhost`. При ошибке подключения локальный запуск не подменяет удалённый. Удалите файл из корня проекта, чтобы вернуться к локальному режиму. Не включайте файл с токеном в репозиторий и не передавайте его как исходный файл проекта.

После копирования структура папки навыка должна быть такой:

```text
1c-batch/
├── SKILL.md - модифициррованный, с добавлением секции в конце (см п.2)
├── scripts/
│   ├── build-epf.bat
│   ├── dump-config.bat
│   ├── dump-epf.bat
│   ├── dump-extension.bat
│   ├── load-config.bat
│   ├── load-extension.bat
│   ├── run-designer.bat
│   └── run-enterprise.bat
└── remote/
    ├── SKILL-REMOTE.md
    └── remote-scripts/
        ├── client_settings.py
        ├── run_bat.py
        └── upload_files.py
```
